\section{Conceitos Básicos}
\begin{itemize}
    \item Arquitetura são os atributos visiveis ao programador
    \begin{itemize}
        \item Conjuntos de instruções, numeros de bits usados para representação 
        de dados, mecanismos de E/S, técnicas de endereçamento.
        \item Exemplo: Existe uma instrução de multiplicação?
    \end{itemize}
    \item Organização é como os recursos são implementados.
    \begin{itemize}
        \item Sinais de controle, interfaces, tecnologia de memória
        \item Exemplo: Existe uma unidade de multiplicação no hardware ou ela 
        é feita pela adição repetitiva
    \end{itemize}
\end{itemize}

Exemplo de Decisão de Projeto
\begin{itemize}
    \item Questão: Presença ou não da instrução de multiplicação.
    \item A decisão deve ser tomada de acordo com: 
    \begin{itemize}
        \item A frequência do uso da instrução
        \item Velocidade relativa das duas técnicas
        \item Custo e tamanho físico de uma unidade de multiplicação especial
    \end{itemize}
\end{itemize}

    \subsection{Função vs Estrutura}
    \begin{itemize}
        \item Função -- É a operação individual de cada componente como parte 
        da estrutura
        \begin{itemize}
            \item As funções do computador são:
            \begin{itemize}
                \item Processamento de dados
                \item Armazenamento de dados
                \item Movimentação de dados
                \item Controle
            \end{itemize}
        \end{itemize}

    \end{itemize}
    \subsection{ENIAC -- Eletronic Numerical Integrator and Calculator}
    \begin{itemize}
        \item Sediado na Universidade da Pensilvânia
        \item É um computador de propósito geral construido entre 1943 e 1946
        \item Realizava cálculos de balística na WW2
        \item Consumiu uma pequena fortuna de \$ 500.000 da época
        \item Ocupava uma área de 150 m$^2$ e pesava 30 toneladas
        \item Era acionado por um motor equibalente a dois potentes motores de 
        carros de quatro cilindros, enquanto um enorme ventilador refrigerava o 
        calor produzido pelas válvulas
        \item Consumia 150.000 watts ao produzir o calor equivalente a 50 
        aquecedores domésticos
        \item Possuia 20 registradores, cada um com capacidade para armazenar 
        um número decimal de 10 algarismos
        \item A programação era feita através de fios e pinos
        \item Executava 5000 adições/subtrações ou 300 multiplicações por segundo
        \item Para programar levava 1 ou 2 dias
        \item Uma grande limitação era a capacidade de armazenamento de dados
    \end{itemize}
    \subsection{John Von Neumann}
    \begin{itemize}
        \item Consultor do projeto ENIAC
        \item Criou o conceito de "programa armazenado"
        \item Criou o conceito de operações com número binários
        \item Desenvolveu a lógica dos circuitos
        \item Memória principal armazenando programas e dados
        \item Unidade de controle interpretando e executando instruções da memória
        \item Criador do modelo de Arquitetura de Von Neumann
        \begin{itemize}
            \item Esta arquitetura foi utilizada no EDSAC, o primeiro computador 
            de programa armazenado
        \end{itemize}

            \includegraphics[width=0.65\linewidth]{imagens/arquitetura_von_neumann.png}

        \begin{itemize}
            \item Unidade de Entrada
            \item Unidade de Saída
            \item Unidade Lógica Aritmética (ULA)
            \item Unidade de Memória
            \item Unidade de Controle (UC)
        \end{itemize}
        \item Memória: 4096 palavras
        \item Cada palavra possuia 40 bits
        \begin{itemize}
            \item Duas instruções de 20 bits
            \item Um dado de 40 bits
        \end{itemize}
        \item ULA + UC = CPU
        \item A Unidade de Controle possuía um registrador de 40 bits (acumulador)
        \item A comunicação entre os componentes é realizada através de um caminho 
        compartilhado chamado barramento de sistema (bus)

    \subsection{Programação em hardware}
    \begin{itemize}
        \item O armazenamento e operação de dados binários e logicos sao 
        realizados a partir da combinação de componentes logicos
        \item A combinação especifica de componentes logicos pode ser feita 
        para realizar calculos especificos
        \item Conexão de componentes lógicos $\rightarrow$ Programa hardwired
        \item A combinação de componentes logicos pode ser feita para a 
        execução de várias funções (uso geral)
        \begin{itemize}
            \item Sinais de controle são aplicados ao hardware
        \end{itemize}
    \end{itemize}
        \subsubsection{Ciclo de Instrução}
        \begin{itemize}
            \item Um ciclo de instrução é composto por duas etapas
            \begin{itemize}
                \item Ciclo de busca
                \item Ciclo de execução
            \end{itemize}
            \item Ciclo de busca
            \begin{itemize}
                \item Contador de Programa (PC) mantem endereço da proxima 
                instrução a buscar
                \item Processador busca a instrução do local de memoria 
                apontado pelo PC
                \item Incrementar PC -- A menos que seja informado de outra 
                forma
                \item Instrução carregada no Registrador de Instrução (IR)
            \end{itemize}
            \item Ciclo de Execução / instrução
            \begin{itemize}
                \item Processador interpreta instrução e realiza as ações 
                exigidas
                \item Categoria das ações:
                    \begin{itemize}
                        \item Processador -- memória
                        \item Processador -- E/S
                        \item Processamento de dados
                        \item Controle
                    \end{itemize}
            \end{itemize}
        \end{itemize}
        \subsubsection{Interrupção}
        \begin{itemize}
            \item Mecnismo pelo qual módulos (como E/S) podem interromper a 
            sequencia de processamento normal
            \item Interrupções podem ser ocasionadas por:
            \begin{itemize}
                \item Falaha de algum programa: divisão por zero, acesso à 
                espaço de memória inválido, overflow
                \item Timer: sinal para indicar o instante da execução de uma 
                função especifica
                \item E/S: sinalizar o termino de uma operação ou ocorrencia de 
                erros
                \item Falha de hardware: falta de energia
            \end{itemize}
            \item Ciclo de Interrupção
            \begin{itemize}
                \item Adicionado ao ciclo de instrução
                \item Processador verifica Interrupção
                \begin{itemize}
                    \item Indicado por um sinal de Interrupção
                \end{itemize}
                \item Se não houver interrupção, busca próxima instrução
                \item Se houver interrupção pendente:
                \begin{itemize}
                    \item Suspende execução do programa atual
                    \item Salva contexto
                    \item Define PC para endereço inicial da rotina de 
                    tratamento de interrupção
                    \item Interrupção do processo
                    \item Restaura contexto e continua programa interrompido
                \end{itemize}
            \end{itemize}
            \item Multiplas interrupções
            \begin{itemize}
                \item Desativar Interrupções
                \begin{itemize}
                    \item Processador ignorara outras interrupções enquanto 
                    processa uma interrupção
                    \item Interrupções permanecem pendentes e são verificadas 
                    após a primeira interrupção ter sido processada
                    \item Interrupções tratadas em sequencia enquanto ocorrem
                \end{itemize}
                \item Definir prioridades
                \begin{itemize}
                    \item Interrupções de baixa prioridade podem ser 
                    interrompidas por interrupções de prioridade mais alta
                    \item Quando a interrupção de maior prioridade tiver sido 
                    processada, processador retorna à interrupção anterior
                \end{itemize}
            \end{itemize}
        \end{itemize}
    \subsection{Conexões}
    \begin{itemize}
        \item Todas as unidades de um sistema computacional precisam estar 
        conectadas
        \item Tipos diferentes de conexão para tipos diferentes de módulos:
        \begin{itemize}
            \item Memória
            \item Módulo de E/S
            \item CPU
        \end{itemize}
    \end{itemize}
        \subsubsection{Conexão da Memória Principal}
        \begin{itemize}
            \item Tipicamente, a memória principal é composta de N palavras de 
            mesmo tamanho
            \item Receve e envia palavras:
            \begin{itemize}
                \item Endereços (de posições)
                \item Dados
            \end{itemize}
            \item Recebe sinais de controle
            \begin{itemize}
                \item Leitura
                \item Escrita
            \end{itemize}
        \end{itemize}
        \subsubsection{Conexão de Entrada/Saída}
        \begin{itemize}
            \item Similar à memória, do ponto de vista da CPU
            \item Caada interce (porta) é identificada por um endereço
            \item Operação de Saída
            \begin{itemize}
                \item Recebe dados do computador
                \item Envia dados para a interface do dispositivo externo
            \end{itemize}
            \item Operação de Entrada
            \begin{itemize}
                \item Recebe dados da interface de um dispositivo externo
                \item Envia dados para o computador
            \end{itemize}
            \item Recebe sinais de controle do computador
            \item Envia sinais de controle para os dispositivos externos
            \begin{itemize}
                \item Ex.: Ligar motor do disco rígido
            \end{itemize}
            \item Recebe endereços do computador
            \begin{itemize}
                \item Ex.: Número da porta para identificar periférico
            \end{itemize}
            \item Envia sinais de interrupção (controle)
        \end{itemize}
        \subsubsection{Conexão da CPU}
        \begin{itemize}
            \item Lê instruções e dados
            \item Escreve dados (após processamento)
            \item Envia sinais de endereçamento para outras unidades
            \item Envia sinais de controle para outras unidades
            \item Recebe (e processa) as interrupções
        \end{itemize}

    \subsection{Barramento (BUS)}
    \begin{itemize}
        \item Há diversas maneiras de se projetar um sistema de interconexão
        \item Mais comuns: 
        \begin{itemize}
            \item Barramento separado em linhas de dados, endereço de controle
            \item Barramento compartilhado (multiplexado) para vários tipos de 
            informação (i.e.: dados e endereços)
        \end{itemize}
        \item Meio de comunicação entre dois ou mais dispositivos
        \item Sinais colocados em um barramento são recebidos por todos os 
        dispositivos (broadcast)
        \item Apenas um módulo pode escrever em um barramento em um dado instante
        \item Geralmente é agrupado:
        \begin{itemize}
            \item Vários canais de comunicação em um só barramento (barramento 
            paralelo)
            \item Barramento de dados de 32 bits é um conjunto de 32 canais de 
            1 bit
        \end{itemize}
        \item Nos modelos não se representam as conexões para a fonte de tensão
        \item[] imagem
        \item No diagrama acima o barramento está dividido em:
        \begin{itemize}
            \item Brramento de dados
            \item Barramento de endereço
            \item Barramento de controle
        \end{itemize}
    \end{itemize}
        \subsubsection{Barramento de Dados}
        \begin{itemize}
            \item Transmite dados
            \begin{itemize}
                \item Observe que não há distinão entre "dado" e instrução neste 
                nivel (fora da CPU)
            \end{itemize}
            \item Largura do barramento é um fator determinante no desempenho (via 
            da regra, quanto mais largo, melhor)
            \item Largura de barramento de dados comuns:
            \begin{itemize}
                \item 8 bits (Intel 8088)
                \item 16 bits (Intel 8086)
                \item 32 bits (Intel Pentium)
                \item 64 bits (Intel Xeon -- Core2Duo/Quad -- Core i3/5/7)
            \end{itemize}
        \end{itemize}
        \subsubsection{Barramento de Endereços}
        \begin{itemize}
            \item Usado para identificar a fonre e o destino dos dados que 
            trafegam no barramento de dados
            \item Ex.: CPU precisa ler uma instrução (dado) de uma determinada 
            posição na memória
            \item Largura do barramento de endereço determina a capacidade de 
            memória máxi-ma do sistema
            \begin{itemize}
                \item Ex.: Z-80 tem um barramento de endereço de 16 bits. \\
                Memória máxima: $2^{16}=65.536$ posições de memória.
            \end{itemize}
        \end{itemize}
        \subsubsection{Barramento de controle}
        \begin{itemize}
            \item Controle e temporização das infomações
            \begin{itemize}
                \item Sinais de leitura e escrita para a memória principal para 
                dispositios de E/S.
                \item Requisições de interrupção
                \item Sinais de controle gerais, tais como:
                \begin{itemize}
                    \item Requisição de uso do barramento por um módulo
                    \item Término de uso do barramento
                    \item Inicialização (reset) de dispositivos, etc.
                \end{itemize}
            \end{itemize}
        \end{itemize}
        \subsubsection{Aspectos fisicos dos barramentos}
        \begin{itemize}
            \item Conectores de borda de placa de expansão (Ex.: PCI)
            \item Cabos paralelos
            \item Linhas paralelas em placas de circuito impresso
        \end{itemize}
        \subsubsection{Barramento Único}
        \begin{itemize}
            \item Apesar de ser mais simples de implementar, há desvantagens de se 
            usar um unico barramento de sistema
            \begin{itemize}
                \item Condutores longos: tempo maior de propagação
                \item Muitos dispositivos ligados no mesmo meio de transmissão 
                significa que a coordenação do uso do barramento pode afetar o 
                desempenho geral do sistema
                \item E se houver dispositivos com diferentes velocidades de 
                transmissão ligados ao barramento?
                \begin{itemize}
                    \item Taxa de transferência total de dados é limitada à taxa de 
                    transferência no barramento do sistema
                \end{itemize}
                \item Solução: Usar múltiplos barramentos
            \end{itemize}
        \end{itemize}
        \subsubsection{Classificação de Barramentos}
        \begin{itemize}
            \item Dedicado
            \begin{itemize}
                \item Linhas separadas para dados e endereços
            \end{itemize}
            \item Multiplexado
            \begin{itemize}
                \item Linhas compartilhadas
                \item Necessita de mais uma linha de controle, para indicar se 
                há dados ou endereços trafegando no barramento naquele instante
                \item Vantagem: Necessita de menos condutores
                \item Desvantagens:
                \begin{itemize}
                    \item Controle mais complexo
                    \item Pode diminuir o desempenho (pois compartilha um só 
                    canal para endereços e dados)
                \end{itemize}
            \end{itemize}
        \end{itemize}
        \subsubsection{Arbitragem do Barramento}
        \begin{itemize}
            \item Apenas um módulo pode controlar o barramento por vez (apesar 
            de mais de um módulo poder ler o que está sendo transmitido)
            \item O que acontece se mais de um módulo solicitar o controle do 
            barramento?
            \item Claramente, precisamos estabelecer regras para ceder o 
            controle do barramento: Arbitragem do Barramento 
            \item As regras definem mestre (que controla) e escravo(s) (que é/
            são controlados)
            \item A arbitragem pode ser centralizada ou distribuida
            \item Tipos de Arbitragem
            \begin{itemize}
                \item Centralizada
                \begin{itemize}
                    \item Somente um módulo controla o acesso ao barramento
                    \begin{itemize}
                        \item Controlador de barramento ou árbitro decide quem 
                        poderá controlar o barramento
                    \end{itemize}
                    \item Pode ser parte da CPU, ou um dispositivo dedicado a 
                    essa tarefa
                \end{itemize}
                \item Distribuida
                \begin{itemize}
                    \item Cada módulo pode decidir controlar o barramento
                    \item Necessária lógica de controle em todos os módulos
                \end{itemize}
            \end{itemize}
        \end{itemize}
        \subsubsection{Gargalo de von Neumann}
        \begin{itemize}
            \item Refere-se ao tráfego nos barramentos do computador
            \begin{itemize}
                \item Vai endereço da instrução, volta instrução
                \item Vão endereços dos operandos
                \item Vão e voltam operandos
            \end{itemize}
            \item Para eliminar gargalo: Diminuit tráfego de informações
            \begin{itemize}
                \item Manter informações na CPU $\rightarrow$ Inclusão de 
                registradores
                \item Diminuir tamanho (em bits) das informações transferidas
            \end{itemize}
        \end{itemize}
\section{Aritmética Computacional}
    \subsection{Unidade Lógica Aritimética(ULA)}
    \begin{itemize}
        \item É a parte do computador que de fato executa as operações 
        aritméticas e lógicas sobre os dados
        \item Tudo o mais no computador existe para atender a essa unidade
        \item Todos os outros elementos do computador são usados para:
        \begin{itemize}
            \item Trazer os dados a serem processados pela ULA
            \item Receber os resultados das operações efetuadas
        \end{itemize}
        \item Constitui o núcleo ou a essência do computador 
        \item É baseada em dispositivos lógicos digitais simples, capazes 
        de armazenar dígitos binários e efetuar operações simples de lógica 
        booleana
        \item Os dados são fornecidos à ULA em registradores e os 
        resultados de uma operação são armazenados também em registradores
        \item A ULA pode também ativar bits especiais (flags) para indicar 
        o resultado de uma operação 
        \item[] imagem
        \item A aritmética computacional geralmente opera com dois tipos de 
        números muito diferentes:
        \begin{itemize}
            \item Numeros inteiros
            \item Numeros de ponto flutuante
        \end{itemize}
        \item Em ambos os casos, a escolhja da representação é uma questão 
        crucial de projeto
    \end{itemize}
        \subsubsection{Números Inteiros}
        \begin{itemize}
            \item Representação de números inteiros
            \begin{itemize}
                \item No sistema de números binários, é possivel representar 
                números arbitrários usando os digitos zero e um \
                \[-1101,101_2 = -13,625_{10}\]                
            \end{itemize}
            \item Para armazenar esses números no computador, não é possivel 
            usar os sinais de menos e a virgula
            \begin{itemize}
                \item Apenas os digitos binários (0, 1) podem ser usados
            \end{itemize}
            \item Representação sinal-magnitude
            \begin{itemize}
                \item Utiliza o bit mais significativo da palabra como um bit 
                de sinal
                \begin{itemize}
                    \item Se o bit mais significativo for 0, o numero será 
                    positivo
                    \item Se for 1, o número será negativo
                \end{itemize}
                \item É a forma mais simples de representação
                \[
                \begin{array}{l}
                    +18_{10} = 00010010 \\
                    -18_{10} = 10010010 \\
                \end{array}
                \]
                \item Algumas desvantagens dessa forma de representação
                \begin{itemize}
                    \item Numa operação de adição e subtração é preciso considerar:
                    \begin{itemize}
                        \item A magnitude do número
                        \item O sinal dos dois operandos
                    \end{itemize}
                    \item Existem duas representações de 0:
                    \[
                    \begin{array}{l}
                        +0_{10} = 00000000 \\
                        -0_{10} = 10000000 \\
                    \end{array}
                    \]
                \end{itemize}
            \end{itemize}
            \item Representação em complemento de dois
            \begin{itemize}
                \item Também usa o bit mais significativo como bit de sinal
                \item Os números são escritos da seguinte forma:
                \begin{itemize}
                    \item Positivos: Sua magnitude é representada na sua forma 
                    binária direta, e um bit de sinal 0 é colocado em sua frente
                    \begin{itemize}
                        \item (bit 0) + o número em binário
                        \item Exemplos:
                        \[0001 (+1)\] \[0100 (+4)\] \[0111 (+7)\]
                    \end{itemize}
                    \item Negativos: Sua magnitude é representada na forma de 
                    complemento a 2 (um bit de sinal acaba ficando em sua 
                    frente)
                    \begin{itemize}
                        \item Para um número binário de $n$ bits, o peso do bit 
                        mais significativo é $-2^{n-1}$
                        \[ A = -2^{n-1} a_{n-1} + \sum\limits_{i=0}^{n-2}2^ia_i \]
                    \end{itemize}
                \end{itemize}
                \item Regra para formar a negação:

        \item Hierarquia de memoria:

            \item RAM (Memória de Acesso Aleatório)
            \item Cache

        \end{itemize}
        \item Ao descer na hierarquia, a memória é mais rapida mas com tamanho

        \item O barramento da memoria RAM com o processador é um gargalo e 
        possui uma latencia L
        \item A memoria cache foi criada com o intuito de reduzir esse gargalo, 
        ao inves de buscar apenas uma instrução, busca um bloco com elas, e 
        guarda esse bloco na memória.
        \item É possivel ter niveis diferentes de cache, localizações diferentes, 
        e organizações diferentes.
    \end{itemize}

Cache
\begin{itemize}
    \item Armazena dados e instruções
    \item As instruções tem tempos fixos para a execução de acordo com os 
    circuitos eletronicos do processador
    \item A memória cache não deixa as instruções mais rápidas, deixa o programa 
    mais eficiente
    \item Localidade: 
    \begin{itemize}
        \item Na memória cache temos dois tipos de localidade:
        \begin{enumerate}
            \item Temporal -- Uma região de memória de um determinado dado será 
            acessado com uma constância maior
            \begin{itemize}
                \item Ex.: 
                \begin{verbatim}
        for (int i = 10; i <= 10000; i++) {
            soma += 1;
        }\end{verbatim}
                \item Nesse caso, \verb|soma| é uma variável temporal
            \end{itemize}
            
            \item Espacial -- Os dados próximos ao dado que foi acessado 
            anteriormente, serão acessados também
            \begin{itemize}
                \item Ex.: 
                \begin{verbatim}
        for (int i = 10; i <= 10000; i++) {
            v[i] = i;
        }\end{verbatim}
                \item Nesse caso, \verb|v[i]| é uma variável espacial
            \end{itemize}
            
        \end{enumerate}
        \item Quando o programa possui uma função JUMP, a memória cache busca 
        os dados aos arredores do endereço do JUMP, porém, não é sempre que a 
        cache acessa a memória correta
        \begin{itemize}
            \item Falha (miss) -- Quando o dado ou instrução que o processador 
            precisa não está na Cache
            \item Acerto (hit) -- Quando o dado ou instrução que o processador 
            precisa está na Cache
        \end{itemize}
    \end{itemize}
    \item Fluxo
    \item Hierarquia
    \begin{itemize}
        \item Processador $\rightarrow$ Cache N1 $\rightarrow$ Cache N2 
        $\rightarrow$ Cache N3 $\rightarrow$ RAM
    \end{itemize}
    \item Organização
    \begin{itemize}
        \item Organizada em linhas, onde cada linha é um bloco da memória
        \item Atualmente as máquinas usam em média 3 níveis de memória cache, 
        onde:
        \begin{enumerate}
            \item O nivel um normalmente é dividido em dados e instruções
            \item O nivel dois é unificado, onde não tem um espaço especial 
            para ou dados ou instruções
            \item O nível três também é unificado
        \end{enumerate}
        \item A cache não possui palavras, ela possui linhas, que normalmente 
        contem um numero maior de palavras
    \end{itemize}
    \item Políticas de Substituição:
    \begin{itemize}
        \item LRU -- Least Recently Used
        \begin{itemize}
            \item Retira a linha que está a mais tempo sem ser utilizada
        \end{itemize}
        \item FIFO -- First in, First out
        \begin{itemize}
            \item Retira a linha que está na memória a mais tempo
        \end{itemize}
        \item Random
        \item LFU -- Less Frequently Used
        \begin{itemize}
            \item Retira a linha que foi usada com a menor frequencia dentro do 
            programa
        \end{itemize}
        \item Dependendo da localidade, esses algoritmos podem ser mais e menos 
        eficientes, aumentando os hits ou misses.
        \item gem5 -- Fazer testes, usando o modo SE
    \end{itemize}

        \begin{itemize}
            \item Mais complexa, porém tem custo de memória mais baixo
            \item Cada bloco só é armazenado por linha de cache
        \end{itemize}
        \item Write Through
        \begin{itemize}
            \item Mais simples mas com custo de memória mais alto.

    \begin{itemize}
        \item Decide em qual linha um bloco de memória será armazenado na cache
        \item Temos 3 tipos de mapeamento
        \begin{enumerate}
            \item Direto
            \begin{itemize}
                \item Um bloco de memória é sempre armazenado na mesma linha
                \item Utiliza de um endereço:

                \item Palavra indica qual palavra do bloco de memória será 
                acessado
                \item No mapeamento direto não é util nenhum tipo de politica 
                de substituição, já que o bloco de memória sempre cai na mesma 
                linha
                \item Dentro do mapemento direto, dois endereços podem acabar

                    \item Esse problema pode ser resolvido utilizando do
